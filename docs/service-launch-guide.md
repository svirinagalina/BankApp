# Как поднимать docker compose сервисы и сервисы с специально имеющимся для этого профилем

***

## Немного инфы по работе Spring Boot связанной с профилями

**Spring Boot имеет свое именование**, *по умолчанию* **application** грузится будет всегда,
если не укажете конкретный профиль, причем данные нужного профиля будут накладываться на базовый!

```
application − [имя_профиля]⋅[расширение]
```

|  Компонент  |                      Значение                       | 
|:-----------:|:---------------------------------------------------:| 
| application |                  Базовое имя файла                  | 
| имя_профиля | То, что вы указываете при активации (local, docker) |
| расширение  |              yml, yaml, или properties              | 

### Например наш account-service сервис содержит:

```
application.yml - (default) профиль
application-local.yml - (local) профиль
application-docker.yml - (docker) профиль
```

**Каждый профиль должен подниматься на сервисе исходя из его предназначения,
если это локальный профиль - то через gradlew, если это docker профиль,
то через docker compose**
***

## Если вам нужно поднять сервис через docker профиль, то будем использовать docker compose

### Что у вас должно быть настроено:

1. **Docker Compose YML** со всеми необходимыми параметрами,
   в том числе должен быть такой параметр, связанный с профилем, который подтягивается при запуске:
   ```
   environment:
     SPRING_PROFILES_ACTIVE: docker
   ```
2. Тот самый профиль, который вы хотите запускать из **docker compose**.
   В данном случае ***application-docker.yml***

### Запуск производится из командной строки или терминала:

```
docker compose up -d account-service
```

**up** - использовать ***желательно***, можно и **start**, но почитайте в интернете разницу между ними.   
**-d** - *опциональный флаг*, если хотите не видеть логов при запуске  
**account-service** - название сервиса который вы хотите запустить (поднять)

***

## Если хотите поднять сервис не через изолированную среду как Docker

### Опять же в качестве примера буду использовать account-service.

#### У нас есть **application-local.yml** профиль и его мы можем запустить несколькими способами:

1. Через IDE (**IntelliJIDEA**)  
   Во вкладке **Services** находим наш **AccountServiceApplication**,
   если его нет или нет вообще никаких сервисов и нашего проекта,
   то тыкаем на ➕ или ниже, где написано **No services configured** также на **Add Service**,
   далее **Run Configuration**, в списке выбираем **Spring Boot** и проект с сервисами сам добавится.

* Жмем правой кнопкой мыши по **AccountServiceApplication** и выбираем **Edit Configuration**
* Там в разделе **Build and Run** будет строка **Active profiles** вписываем туда наш профиль,
  а именно - **local**, у вас должно быть так:

```
Active profiles: local
```

Профиль прописывается без дефисов и прочего, поскольку Spring Boot сам его подставляет.

2. Через командную строку, используя Gradle инструмент:

```
./gradlew :account-service:bootRun --args='--spring.profiles.active=local'
```
**:account-service** - название нашего сервиса  
**:bootRun** - исполняемая команда Gradle плагина под Spring Boot  
**--args='--spring.profiles.active=local'** - аргумент для запуска необходимого нам профиля

**The following 1 profile is active: "local"** - в логах говорит об успешном запуске профиля.

***
### Особенности запуска через Gradle

Запускать через gradlew нужно из корня проекта, поскольку могут быть указания на зависимости через другие места,
в **account-service** есть взаимодействие с **bank-bom** и если вы запустите не с корня проекта сервис,
а с места самого сервиса, то получите ошибку при билде.

При этом также есть особенность такого запуска, полоска **EXECUTING** может не доходить до 100%,
поскольку bootRun дает нам возможность взаимодействовать с этим сервисом как бы удерживая его.
Если процесс дойдет до 100% то он вообще завершиться. Кроме этого над **EXECUTING** может быть
написано в логах - (**process running for 3.103**), что говорит об успешном запуске сервиса.
